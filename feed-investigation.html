Why two engines?
The Campaigner handles paid placements and audience-targeted promotions. The Personalizer handles recommendations based on the user's profile, history, and trending content. Running both in parallel keeps the feed fast and balanced.
Pinned promotion

What is "sticky" content?

A small, special category of content the business wants to keep promoting — even after a user has already engaged with it.

📌

Regular top-spot content

Promoted at the top of the feed, but once the user clicks it, it stops appearing. Good for one-time announcements.

🔁

Sticky top-spot content

Keeps appearing at the top of the feed even after the user has clicked, liked, or shared it. Good for ongoing campaigns and high-priority pinned items.

✅
Business value
Sticky content gives the marketing and partnerships team a guaranteed surface for messages that need sustained visibility — without depending on user behaviour to keep them in view.
Safeguards

What protects the user experience

Even sticky content has to earn its place. Six guardrails run on every piece of content before it can appear.

🌍

Region match

Content only shows in the region it was published for.

👩‍⚕️

Role & speciality

Cardiology content stays with cardiologists. Same for speciality, work-site, etc.

🎫

Audience segment

Campaign content checks the user is in the target audience the campaign was built for.

⏰

Expiry

Content past its expiry date is removed automatically.

💰

Sponsored consent

Users who opted out of sponsored content never see it.

📊

Per-type caps

Caps on how many of each content type can appear in one feed.

The user-sync job

Every 2 minutes, the system asks:
"who changed?"

A background job runs on a clock. It picks up users who edited their profile or opened the app, and refreshes their record in the recommendation store.

Safe at scale
Multiple copies of the API run in production. A shared timestamp ensures only one instance does the work each tick — the others see "already done" and skip. No duplicate effort, no race conditions.
Who makes the cut

Two paths to being indexed

A user record is only added to the recommendation store if it meets one of two criteria.

👤

Path A — Real users

  • ✓Account status is accepted, pending, or on hold
  • ✓Has a valid email
  • ✓Has a user ID
  • ✓Has a country set
OR
👻

Path B — Ghost profiles

  • ✓Marked as a "ghost" profile
  • ✓Has a valid email

Ghost profiles are synthetic records — usually practitioners pulled from a public directory who haven't signed up yet.

🚫
Who's excluded
Users in rejected or blocked state, and anyone missing email, user ID, or country. The same job also evicts users who lose eligibility — newly rejected accounts are purged at the next tick.
A useful side-effect

"Don't show me what I've already done"

While the sync job is updating user records, it also remembers what the user has completed — so the recommendation engine stops promoting it.

🎓

Completed CPDs

Once a user finishes a CPD, it's flagged as "done" and removed from future personalized recommendations.

📚

Completed academy courses

Same treatment for finished academy courses — the user moves on, the recommendations move on with them.

👍
Why this matters
Without this, users would keep seeing CPDs they already passed and courses they already completed — wasting feed space and feeling like the system doesn't know them. This is a quiet but important UX win.
Worth flagging

Three things to be aware of

📈
The "completed" list only grows
Once a CPD or course is marked done for a user, it stays on their exclusion list forever. There's no built-in re-engagement mechanism if we ever want to re-promote a re-certification or refresher.
🗄️
Two database reads every 2 minutes per server
Each app instance issues two Firestore queries on every tick before the de-dupe check applies. At today's scale this is fine; worth revisiting if we grow horizontally.
🤐
Quiet error handling on exclusions
If the system fails to record a "completed CPD" exclusion, the error is silently dropped. Low impact (the user just sees content they've finished) but worth knowing — and easy to fix.
